## 文件：FTransUNet/model/vitcross_seg_modeling.py
序号1：
- config是如何引入呢？
	- 我们在train.py中，找到模型实例化的语句`net = ViT_seg(config_vit, img_size=256, num_classes=6).cuda()`
	- 通过实例化的语句，引入config到构造器的形参中，通过config形参，引入到这个模型每个构件的实例化的语句中。
- config内容是什么呢？
	- CONFIGS_ViT_seg是一个字典，键值对分别是版本号：配置信息。我们选择, `config_vit = CONFIGS_ViT_seg['R50-ViT-B_16']`。配置信息是configs.get_r50_b16_config()的返回值。
	- configs.get_r50_b16_config()有两部分构成，第一部分是config = get_b16_config()，第二部分是函数体的定义。config.hidden_size在第一部分中定义了。

序号2：
- features有多少个特征图？它们的形状是什么？怎么知道的？
	- 要知道features中的内容是什么：我们通过class VisionTransformer(nn.Module)中forward，可以得知self.transformer完全充当了编码器的角色，而这个object的类是class Transformer(nn.Module)。Transformer(nn.Module)有两个属性，分别是self.embeddings和self.encoder，根据forward，可以知道self。embeddings充当的就是那一坨卷积的角色，而features就来自于这个坨卷积，它属于这个类class Embeddings(nn.Module)，因此，理解这个类是关键。这个类中的forward方法提到，x, y, features = self.hybrid_model(x, y)，因此，问题又转移到self.hybrid_model对应的类class FuseResNetV2(nn.Module)。
经过检验，features经过CNN后，里面有三个特征图，它们的形状分别是 (512, H/8, W/8),(256, H/4, W/4),(64, H/4, W/4)

- 为什么文章图示是3个解码器模块，而代码是4个模块，且最后一个模块的输出通道是16？
	- 通过对'R50-ViT-B_16'版本的观察，我们发现features确实只有三个，也就是说用于拼接自上而下的特征图与横向连接的特征图的解码器模块有且仅有3个，且最后一个是(64, H/2, W/2)的。
	- 第四个是一个上采样 + 2个卷积操作，可以认为是segmentation head的一部分，这样得到了(16, H, W), 只需要通道维度16-->6即可。



序号3：
- forward中，输入这个VisionTransformer的形状是什么？
	- 思路：实例化后的模型，在train()中，需要计算pred用于计算loss。`output = net(data, dsm)`, 这里data，dsm是什么形状呢？肯定是dataloader提供的batch形状相同，而batch中的每个实例的shape跟dataset有关。在这个项目中，dataset是ISPRS_dataset对吧。ISPRS_dataset，定义两个方法，一个是`__getitem__`, 一个是`__len__`， `__getitem__`定义了形状。看到`return (torch.from_numpy(data_p),torch.from_numpy(dsm_p),torch.from_numpy(label_p))`, 就知道shape就是(batch size, channel, H, W)

- x + y是什么意思？
	- 通过编码器后，x，y分别得到x，y，然后通过+进行融合呗

序号4：
- 通过编码器后，用于解码器的数据都是什么？
	- features：
		- (512, H/8, W/8)
		- (256, H/4, W/4)
		- (64, H/4, W/4)
	- reconstructed的Zn：
		- (512, H/16, W/16)
- 4个decoder block的工作工程？
	- 三个channels：
		-  对in_channels, 应该是`[512, 256, 128, 64]`
		- 对skip_channels，应该是`[512， 256， 64， 0]`
		- 对out_channels, 应该是`[256, 128, 64, 16]`
	
	- 过程：（in_ch, sk_ch,  out_ch）
		- 第一个block，(512,  512, 256) --> (256, H/8, W/8)
		- 第二个block，(256, 256, 128) --> (128,  H/4, W/4)
		- 第三个block, (128, 64, 64) --> (64,  H/2, W/2)
		- 第四个block，(64, 0, 16) --> (16,  H, W)
	- 因此最后的segmentation head只需要通道上映射更多即可，不需要再空间维度上采样了。
