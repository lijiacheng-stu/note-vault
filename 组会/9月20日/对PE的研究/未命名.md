我想研究位置编码相关的问题。我现在学了两种位置编码，绝对位置编码（trainable PE）和相对位置编码(RPE, RoPE, ALiBi)。

1. 我学习过程中，我产生了这样的认识：
	- 绝对位置编码和相对位置编码的形式上的本质区别在于注意力分数是绝对位置的函数，还是相对位置的函数。score = f(q, k, i, j) score = f(q, k, i-j)。这两者是有区别的，例如q，k相同的情况下，（q,k,3, 5）（q,k,5, 7）在绝对位置编码值会不同，而相对位置编码值则相同。
	- 绝对位置编码的缺点：
		- 长文本的建模能力差：模型对绝对位置具有较强的依赖，但是训练数据对高绝对位置关系的覆盖不足。例如，一个序列有(小位置, 大位置)，覆盖了（小位置，小位置），（小位置，大位置）或(大位置，小位置)， （大位置，大位置）中，（大位置，大位置)之间的关系，但是对超大位置对这些位置的关系没有覆盖到，因此对长文本建模能力自然差。 相对位置编码能大幅减少这种不平衡，因为（大位置，大位置）、（小位置，小位置）（超大位置，超大位置）这类关系同属于一类关系了。第二个原因是：对于文本相对距离越近越关联的局部性归纳偏差没有引入到模型，（因为没有说相对位置近对应的权重就大，RNN就引入了，卷积核认为和特征图的空间维度一样大，只有关注的像素点周边的有权重，其他为0）需要模型自己学习。
		- 长度外推能力弱：推理时，在处理超过 Max Length 的序列时，由于出现了训练过程中不存在的绝对位置，模型没有学习过这些位置对应的位置表示，因此难以正确建模这些新位置上的 token 关系，导致模型性能下降。相对位置能够缓解，RPE 建模的是**相对位置**而非绝对位置，因此当推理序列超过 Max Length 时，即使出现了训练阶段未出现的绝对位置，模型仍然可以利用已经学习过的相对位置关系。以超出 Max Length 的 token 为例，它与附近 token 的相对距离通常仍然落在训练阶段已经学习过的范围内，因此这些局部关系仍然可以被较好地建模。同时，自然语言具有一定的**局部性归纳偏差**：局部 token 之间通常具有更强的关联，因此即使某些超长序列中的远距离关系泛化较差，对整体建模能力的影响也可能相对有限。
		- 内容-位置耦合：绝对位置编码将 Token Embedding 与 Position Embedding 直接相加，使内容信息与位置信息耦合在同一个表示中，模型需要自行学习二者的关系。
	- 结论：
		- 通常应该使用相对位置编码
		- 尽量找到参数数量少的算法
		- （特定情况有效）引入局部性归纳偏差

2. RPE
	2.1 算法介绍：
	- 每一个可能的相对位置，关联一个训练参数bias
	- `q*k` 后，根据q，k的相对位置，加上对应的bias，得到score
	- 注意：对超过Max length的相对位置，直接截断
	2.2 算法本身的特点：
	- RPE 将内容相关性与相对位置关系分别建模，在 Attention Score 层面进行融合，使模型不必从混合的内容-位置表示中自行分离位置信息，从而降低了学习二者关系的负担。
	2.3 性能分析：
	- 训练参数是否更少？可能大也可能少
	- 局部性先验偏差是否引入？无
