1. perceiver中的latent tokens
	- pixel tokens这种数量大的作为KV，latent tokens数量少的作为Q，作交叉注意力。**这样能用比较少的算力得到整个图像的表示。** 让从最基本元素进行建模成为可能，减少归纳偏差，提高建模能力。
	- perceiver IO用perceiver中得到的用于表示整个图像的latent tokens作为KV，用output query token作为Q，可以解决各类问题。分类任务，使用一个output query token；MLM任务，将掩码的位置编码作为output query token；对于optical flow，让perceiver的input和output query token相同 。
2. clip的contrastive loss
	- 对于熟悉的交叉熵损失，我们是先计算这个batch中每一个instance的loss，然后求平均。这就相当于每个instance是单打独斗的。
	- clip把image和text对分别通过对应的编码器编码成一个向量。一个batch就有m个image和text对。站在一个image的角度上，同一个instance的是匹配的（positive example），不同instance的是不匹配的（negative example）。我们计算每个图片对每个text的预先相似度，让匹配的尽量为1，不匹配的尽量为零（即，相似度矩阵的对象线是1，其他是0）。（当然后面temperature，在转化成交叉熵）。但是这种损失的设置，就是整个把batch来构造的。
3. 在考虑无限并行的情况下，以矩阵乘法为例，理解gpu的工作原理：
	- 设矩阵Q是Lq,Ld，矩阵K是Lk,Ld，现在计算Q@K.T
	- 我们的gpu能够优化矩阵运算，让矩阵的所有cell的值的计算并行执行。这种局面下，一个cell计算的时间就是整个矩阵计算的时间。一个cell的时间是多少呢？它是点积操作。矩阵计算的时间 = 一个点积操作的时间
	- 在点积操作中，因此元素之间相乘是并行的，因此需要1个乘法的时间。相加是**树状归约**执行，需要⌈log2​Ld​⌉个计算加法的时间。因此，最后矩阵计算的时间是应该是1个乘法的时间 + ⌈log2​Ld​⌉个算加法的时间，和Lq和Lk没有关系。
	- 时间复杂度的计算应该考虑穿行执行的情况。
