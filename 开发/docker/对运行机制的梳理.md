1.1 其他子进程的启动不会引起bash状态的变化，都是Ss，只是让这个bash所在session的前景进程组变化了。
1.2 terminal emulator 关闭 → PTY master 关闭 → tty driver 发现 hangup → 内核向 session leader 发送 SIGHUP。bash 作为 session leader 收到 SIGHUP 时，默认会向自己管理的 jobs（通常是它的 job process groups）发送 SIGHUP，然后退出；如果 SIGHUP 被忽略或捕获，则可以不退出。
1.3 jobs, bg, fg命令都是shell的内置命令。但是session，process group，process但都是unix通用的概念。当向shell发送jobs时，以当前这个shell的pid为索引，查看所有sid为pid的进程，然后以pgid进程分组。每一组，作为一个job返回。bg，fg可以类似实现。


1.1  在terminal emulator输入`docker exec -i ccenv cat`时，会让shell在PATH中寻找命令，找到后执行时会fork新的进程执行docker命令，这个进程就可以认为是docker client。docker client 按照`exec -i ccenv cat`信息，执行操作，成为前景进程组。



`docker exec -i ccenv <命令>` 执行后，`ctrl + c`会让docker client关闭。



localhost侧，terminal与docker的client通过tty相连，但是使用raw mode。docker的client与docker的服务器端通过网络相连。docker的服务器端与cat管道直接相连，整个过程没有line discipline使得ctrl+c变为SIGINT信号，因此不应该让cat关闭
